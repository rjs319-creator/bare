# Lane 2 — Backtesting, statistical validation & research tooling

## Lane summary
Ran 20 `gh search repos` queries (engines, DSR/PBO/CPCV/SPA/Romano-Wolf/block-bootstrap, Fama-French/Barra, PIT data, JS/TS stats) plus ~40 direct `gh api repos/...` verifications; ~55 unique repos screened, 15 kept. Headline: **no backtesting engine is worth adopting** — the site's "backtest" is event-study (pick date → 1/5/10/20d excess vs SPY), which vectorbt/zipline/Lean add nothing to except an independent cross-check, and one offline vectorbt script is enough for that. The real wins are (1) **stdlib-js** stat packages as vendorable test oracles for `pFromT`/`fdrAdjust` and a schema fix for the 2dp defect; (2) **purgedcv** + **arch** offline as independent CPCV/PBO/DSR and SPA/StepM reference implementations (the site has no Reality-Check-style "best of N vs benchmark" test at all); (3) a tiny **Ken French factor loader port** feeding the already-existing `lib/orbit-factor-model.js` so Scoreboard excess-vs-SPY becomes alpha-vs-FF5+MOM, validated offline with **alphalens-reloaded**/**linearmodels**; (4) **fja05680/sp500** historical constituents for a survivorship-free benchmark universe. Also audited: `lib/research/stats-v3.js` already has a proper Student-t CDF (regularized incomplete beta), `lib/evolve-dsr.js` already implements DSR, `lib/research/pbo.js` already implements CSCV-PBO — so the p-value defect is a **serialization** problem (see Top proposal 1), not a missing-math problem.

## Top proposals

### 1. Kill the 2dp p-value defect: full-precision schema + stdlib oracle tests (ADOPT, S)
**Finding.** `lib/evidence-stats.js` rounds `avg`/`ci95`/`tCI`/`bootstrapCI` to 2dp and `se` to 4dp before persisting; `pValueOf` falls back to rounded `avg`/`se` for pre-`avgExact` summaries, and any gate reading `ci95.lo > 0` is quantised to 0.01%. `pFromT` itself (stats-v3, regularized incomplete beta) is fine. **What to build:** persist `exact: {avg, se, ci95, tCI, bootstrapCI, ess}` alongside display fields; move rounding to the renderer (`public/js` evidence views); one-off migration in the nightly `warm` chain recomputing legacy summaries from their date series; `fdrAdjust` reads exact p only. **Where:** `lib/evidence-stats.js`, `lib/research/hypothesis-registry.js`, `lib/evidence-routes.js`. **Integration:** add `@stdlib/stats-padjust`, `@stdlib/stats-base-dists-t-cdf`, `@stdlib/stats-ttest` as **dev-dependencies only** (runtime deps stay at 3); property tests assert `pFromT`/`fdrAdjust` match stdlib to 1e-10 across df 2–500 and that BH on exact vs 2dp p flips no verdict on the current registry. **Risk:** low; Apache-2.0; stdlib packages are tiny and ESM-safe. **Measure:** count of registry verdicts that change after migration (expected: a few borderline demotes/promotes).

### 2. Independent CPCV/PBO/DSR + SPA/StepM cross-check (RESEARCH-ONLY, M)
**What:** `research/101-overfit-crosscheck.py` reads the same dates×variants matrices `lib/research/pbo.js` consumes (export them as JSON) and recomputes PBO, PSR/DSR, MinBTL and effective trials with **purgedcv**; disagreement > 0.02 in PBO or > 0.05 in DSR fails CI. Second step: **arch** `SPA`/`RealityCheck` over the full family of live screeners vs SPY ("does the best screener beat the benchmark after accounting for all we tried?") and `StepM` as a Romano-Wolf stepdown alternative to BH — this test does not exist in the site and is the right one for "N strategies, one benchmark". **Where:** `research/` (Python already used: `28-mlrank.py`…`37-gap-interactions.py`); outputs a JSON verdict the registry can display as a "cross-check" badge. **Risk:** Python-only (offline fine); arch NCSA and purgedcv MIT permit porting; `StepM` is ~150 lines → PORT to `lib/research/stepm.js` once validated. **Measure:** shadow badge per hypothesis; promotion gates unchanged until 3 months of agreement.

### 3. Factor-adjusted Scoreboard: Ken French loader port + ETF-proxy factors (PORT + data pipeline, M)
**What:** make "beats the market" = **alpha vs Mkt-RF, SMB, HML, RMW, CMA, MOM**. (a) Port pandas-datareader's famafrench reader to `lib/factors/ken-french.js` (fetch the Dartmouth zip, parse CSV, cache in Blob — no key, no dep); (b) because French daily files lag ~1 month, extend the existing `lib/orbit-factor-model.js residualWindow` (now sector-ETF only) with **style-ETF proxies** (IWM−SPY, IWD−IWF, MTUM−SPY, QUAL−SPY) for live 1–20d windows; (c) Scoreboard adds `alphaFF` next to `excessSPY` with HAC t-stat. **Where:** `lib/orbit-factor-model.js`, Scoreboard summariser (`summary.json` writer), `public/js` Scoreboard tab. **Validation offline:** `research/102-factor-alpha.py` with **alphalens-reloaded** (IC decay/quantile returns of the Session Board grade) and **linearmodels** Fama-MacBeth on true FF factors; ETF-proxy betas must correlate > 0.8 with FF betas or the live column stays shadow. **Risk:** multicollinearity with few observations per pick — report shrunk betas (ridge) and require n ≥ 60 days; FF data terms allow research use. **Measure:** preregister "alphaFF ≥ 0 with q ≤ 0.1" as a new gate run in shadow for 6 months; flag how many currently-Validated hypotheses lose significance once factor-adjusted (the likely outcome given the "momentum = survivorship" history).

### 4. Survivorship-free benchmark universe from historical S&P 500 constituents (ADOPT data, S)
**What:** vendor `fja05680/sp500` CSV (MIT, ~950 stars, refreshed monthly) into `research/data/` and `lib/pitdata`, giving PIT index membership 1996→now. **Uses:** base-rate denominator for "beat rate" that includes names later deleted; audit of `research/04-survivorship-bias.js`; independent check of CERN index-add event dates. **Integration:** offline script + a small JSON snapshot; **risk:** no small-cap coverage (S&P 500 only), so complement, not replacement, for the 2,573-delisting secmaster. **Measure:** re-run momentum baseline (`research/05`) on PIT-membership universe; report delta.

### 5. One vectorbt cross-check of the Scoreboard harness (RESEARCH-ONLY, S)
Single `research/103-vbt-scoreboard-parity.py`: feed vectorbt the persisted pick ledger (ticker, entry date, next-open fill, 1/5/10/20d exits) and compare per-pick excess vs SPY and aggregate beat-rate against `summary.json`. Purpose is to catch PIT/fill/next-open bugs in the JS harness (the 2026-08 audit found 6 such defects), not to replace it. Reject backtesting.py (AGPL), zipline-reloaded/Lean/nautilus (heavy infra, portfolio-sim semantics the site does not use).
